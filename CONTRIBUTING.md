# Contributing

Thank you for helping improve these projects.

## Before starting

1. Read the repository README, current status, and project-specific instructions.
2. Check existing issues and pull requests before opening duplicate work.
3. Confirm that the proposed change is inside the repository's currently authorized scope.
4. Never bypass a frozen stage gate, accepted checkpoint, security boundary, or owner-approval requirement.

## Pull requests

- Keep each pull request focused on one clearly described outcome.
- Explain the problem, approach, affected areas, verification performed, and remaining risks.
- Include tests or reproducible evidence appropriate to the change.
- Preserve backward compatibility unless a breaking change is explicitly approved.
- Do not mix documentation cleanup with unrelated product behavior changes.
- Do not claim production readiness without current evidence.

## Security and privacy

Never commit credentials, access tokens, private keys, personal records, production data, customer data, or unredacted logs. Use safe placeholders in examples and follow the security policy for vulnerability reports.

## Review

A contribution is not accepted until required review and qualification gates pass. Maintainers may request changes, split the work, defer it to a later milestone, or close it when it conflicts with the project's scope.
